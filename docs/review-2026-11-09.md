# Code review, 2026-11-09

A whole-code pass for bugs and for work the app does for nothing. Twelve
readers took one area each (the dashboard runtime; the bars, settings and
setup flows; the vehicle bus and OBD; the head-unit firmware integration; the
network and the AI; the phone companion; the link, the Pi display and the
second screen; embedded apps, the shells and the reverse view; the skins in two
halves; the tiles; the widget faces, alerts and overlays; the build, CI, tools
and tests). Every finding below was checked against the code again before it
was fixed or listed. Nothing was built or run on a unit: Android's SDK could not
be fetched from the review machine, so the Android changes were only parsed by
the Kotlin compiler (no syntax error in the 85 files touched); the pure JVM
modules (`:link`, `:display`, `:unitproto`, `:roadreplay`) were built and their
tests run and extended. CI runs lint and every unit test on this branch; items
marked **car** want a drive before they are trusted.

Items the 2026-10-29 review (and the earlier ones) list are not repeated unless
they were found still open. Paths are under
`app/src/main/java/com/openauto/dash/` unless written in full.

## Taken up on 2026-11-10

Decisions the first pass left open, now taken in code (none built on a unit; CI's lint and tests are the check):

- **Gemini's `do_action` is an allowlist** (media, volume, navigation, status, paging, read message, the call actions); the accessibility, voice, LPG and screen-focus actions are no longer offered to the model. **Tool calls run beside the socket consumer**, so a slow tool no longer delays the voice or the barge-in. **The root probe on a Gemini Live tap runs off the main thread**; the tap waits for the answer already in flight.
- **The tile env is built once over holders of the latest callbacks** (`DashboardGrid.TileContent`): the per-tile `SkinTileEnv` no longer changes on every root recomposition. The per-page lambdas themselves are still new each time (the rest of the cascade item stands).
- **Shizuku and installer shells**: the output builder is synchronised and stops taking lines once the result is taken; the Shizuku command's pid is read and its whole tree killed on a timeout. **`WheelMonitor.sniff` streams through `RootShell`** (pid tracking, `killTree`).
- **`PipAnchor`'s loan, cooldowns and `checkedAt` run on the monotonic clock**; `lastTouchAt`/`ownLaunchAt` stay on the wall clock because `UnitPhoneScreen` compares them with it.
- **Volumes in the driver's units**: `UnitSystem.volume()`/`volumeText()` (US or UK gallons under mpg) on Cockpit, Clay and the OBD data tile; the string resources with "L" in them are unchanged.
- **The volume bar has a `showing` flag** like the call alert, so it cannot show twice while reversing; **alert stacking uses the absolute gravity** (right-to-left languages); **the Canvas rain label ticks**; **the edit bar measures its labels once**; **the wheel map collects the accessibility service's own `connected` flow** instead of polling twice a second; **the Settings search indexes** the OBD sheet's switches, the About rows, Beta updates and Previous version.
- **Companion**: the caller lookup and photo decode run on the worker, published by generation; the recorder's overlay formats its strings per sample and reuses its paths; the notification icon cache is dropped for an updated package; the tab state survives the full-screen builders; the "ago" and day headings tick.
- **Pi and link**: `SignFinder` keeps a per-thread scratch; `Luma.fromRgba` reads one int per pixel; the painter caches fonts; card tiles are decoded on the fetch worker and a queued key moves to the front without rebuilding the queue; the manual tools among the tests are skipped when their inputs are absent; `IdleGuardTest`, `MapTest` and `RootShellSessionTest` no longer sleep against fixed timeouts.

## Found, not changed

Each needs a car, a measurement or a design choice first.

- **Root recomposition still cascades into every page** (10-29 "Found, not changed"): the per-page lambdas handed to `DashboardPage` and `DashboardGrid`'s `tileContent` are new on every root recomposition (`currentPage`, the minute clock, `updateStatus`…), so no page skips (`AutomotiveDashboard.kt` ~1496-1547, `DashboardGrid.kt` ~179-201). The tile env is stable since 11-10; a `remember`ed callback bundle per page is what remains; verify with the Compose compiler reports.
- **Driver-typed and AI readings that stop answering starve the speed/RPM poll** (`MyReadings.pollLoop`, `PidExplorer`: three unanswered requests cost ~4.5 s per 2 s under the command mutex; the 3 s TTL then expires the speed): a per-request miss counter and a skipped header group. **(known) `sendCommand` still spins on `available()`** at up to 200 wake-ups a second for the life of the link.
- **The first door or call alert on a unit without the overlay permission waits on a root shell** (`PipAnchor.grantOverlayPermission` inside the style collector, up to ~2 s plus a Magisk prompt): launching it beside the collector loses the first alert instead; needs a unit to judge.
- **Deep OBD's and the TPMS app's exported receivers take car data from any app** (no sender check is possible for third-party broadcasts); **`BootReceiver` listens to vendor boot actions that are not protected broadcasts**. Low risk, documented here.
- **Motorsport's race and Modern's arrival strip keep the previous route's start and plan when the destination changes mid-guidance** (keyed on `nav.active`, a process-global written in composition): key them on a route identity.
- **Modern rasterises its whole-page city bitmap on the main thread in the draw cache** (Spatial does the same work on `Dispatchers.Default`); **palette-keyed draw caches rebuild on every frame of the 400 ms colour fade** (Futuristic, Clay, Cockpit); **`DashColors.Sync` writes state during composition** (an extra whole-dashboard pass per theme change).
- **Each H.264 access unit is copied three times on the head unit and four on the Pi** (known, confirmed); **the Pi allocates 2.4 MB per picture in `bgrx()`** (GstProcess's pump writes the handed-over array asynchronously, so a safe double buffer needs a completion signal first).
- **CI**: the release job never checks the signature of the APKs it publishes (an `apksigner verify --print-certs` against the key's known SHA-256 would catch a rotated secret; the digest was not available here); the release job starts with a cold Gradle cache; a pre-release and a tag are published for every push to every branch.
- **Tests**: `SteeringWheelStore`'s JSON round trip and `PhoneObd`'s stream have no tests.
- **Settings**: `BarSize.Scaled` and several `remember {}` blocks read preferences in composition; the bar's readouts are subcomposed up to three times per layout; app icons are rasterised again after every package change (the cache is keyed by `Drawable` identity).
- **`gradle.properties` carries AGP 9 migration flags** that AGP 8.13 ignores and that will change behaviour silently on the upgrade; `display`'s version is a hard-coded "1.0".
- Two layouts' first load clamps cells to the new grid before `reflow` anchors them (tiles bunch toward the middle); `ScreenShape.vertical` is written during composition; the Canvas weather tile's rain label reads the clock in composition; the alert preview's caller is a French number in every language (known); `FaceTrends` is keyed by the localised title.
